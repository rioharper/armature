# Onshape live-model checks — what the REST API offers armature-cad

Ticket: [#36](https://github.com/rioharper/armature/issues/36). Researched 2026-09-10 against Onshape's own sources: the developer guides at onshape-public.github.io, the OpenAPI document served at `https://cad.onshape.com/api/openapi` (spec version `1.220.87559`, current server `https://cad.onshape.com/api/v17`), the FeatureScript standard-library reference, and Onshape's help and pricing pages. No secondary write-ups. Sources are numbered `[n]` and listed at the end.

## Answer

Onshape's REST API covers armature-cad's loop-closing check well and the rest of the SolidWorks MCP's surface unevenly. Mass properties come from three read endpoints (Part Studio, single part, assembly) that return mass, centroid, inertia tensor, principal inertia and axes with tolerance min/max bounds, computed about the center of mass like the in-product tool [1][2][3][4]; reporting them about a named frame (the joint origin `armature-derive` used) is a client-side parallel-axis shift from the centroid, or a FeatureScript evaluation with `evApproximateMassProperties(referenceFrame: evMateConnector(...))` in a Part Studio [5][6]. Variables read 1:1 from any element's variable table [7]; writing them is a different shape (a Variable Studio takes `setVariables`, a Part Studio `Variable` feature is edited as a feature, values are expression strings with units, and regeneration is implicit) [8][9][10]. There is no rebuild, no "open document", and no named-dimension addressing: feature status is read from `featureStates` on the feature list, and sketch dimensions live inside sketch constraints keyed by id [11][12]. Tolerances exist on Part Studio dimensions with the same types SolidWorks offers, but the public spec leaves the tolerant-quantity parameter's fields undocumented, so the write path is unconfirmed [13][14]. Custom properties map to the metadata endpoints keyed by `propertyId`, but defining new keys needs company-owned documents on a Professional/Enterprise plan [15][16]. Configurations are fully readable and writable, and every read endpoint accepts a `configuration` query string [17][18]. STEP export is an asynchronous job: POST `export/step` (AP242/AP203/AP214), poll `/translations/{tid}`, download from `externaldata` [19][20][21]. Interference has no REST endpoint at all; the in-product tool exists [22], and a Part Studio can be checked through FeatureScript `evCollision` [23]. Auth is API keys (Basic or HMAC-signed; individual accounts capped at two keys, scoped `OAuth2Read`/`OAuth2Write`) or OAuth2 authorization-code (60-minute access tokens, required only for App Store apps) [24][25][26]. Per-endpoint rate limits are unpublished (429 with `Retry-After`), and the binding constraint is the annual quota: 2,500 successful calls per user per year on Free, Standard and EDU Student, 5,000 on Professional, 10,000 on Enterprise, then 402 [27][28]. The Free plan is non-commercial with every document public [29]; its API allocation is stated explicitly in the limits table, so API access on Free is documented by the developer docs even though the pricing grid lists "Open API Integration" as a compared feature whose per-plan ticks the static page does not reveal [27][29]. Scorecard against the nine SolidWorks tools: 2 map one-to-one (`sw_get_params`, `sw_mass_properties` about the COM), 6 need a different shape, 1 has no equivalent (`sw_open`).

## Mapping — the nine SolidWorks MCP tools

The SolidWorks side is `mcp/solidworks/server.py` (tool signatures) and `mcp/solidworks/sw.py` (what each returns). Onshape paths are relative to `https://cad.onshape.com/api/v{N}` and use `d/{did}` document, `w|v|m/{id}` workspace/version/microversion, `e/{eid}` element (tab); writes always target a workspace [30].

| SolidWorks tool (returns) | Onshape endpoint(s) | Verdict | Note |
|---|---|---|---|
| `sw_status` — SW version, open documents, active document | `GET /users/sessioninfo` (`sessionInfo`) [31]; `GET /documents/{did}` (`getDocument`) [32]; `GET /documents/d/{did}/{wvm}/{wvmid}/elements` (`getElementsInDocument`, filter `elementType=PARTSTUDIO\|ASSEMBLY\|...`) [33] | different shape | No app to attach to and no "open" set. The health call is `sessioninfo` (also proves the key's scope); the inventory call is the element list, which carries each tab's `lengthUnits`/`massUnits`. Version: the API is versioned in the path, not the product. |
| `sw_open(path)` — opens/activates by file path | — | no equivalent | Nothing to open; a model is addressed by `did/wid/eid`. Replace with ID resolution: parse the document URL `cad.onshape.com/documents/{did}/w/{wid}/e/{eid}` or look the tab up by name in `getElementsInDocument` [33]. |
| `sw_get_params(doc)` — all global variables with values in document units | `GET /variables/d/{did}/{wv}/{wvid}/e/{eid}/variables?includeValuesAndReferencedVariables=true` (`getVariables`, "Get the contents of all variable tables in an element") [7] | 1:1 | Works on a Part Studio (its `Variable` features form the table) and on a Variable Studio. Each row is `{name, type: LENGTH\|ANGLE\|NUMBER\|ANY, expression, value, description}`; `value` is a *formatted* string, not a float, so the client parses units [7]. Accepts `configuration` [7]. |
| `sw_set_params(doc, values)` — set existing globals, rebuild, return new values; never creates | Variable Studio: `POST /variables/d/{did}/w/{wid}/e/{eid}/variables` (`setVariables`, body `[{name, type, expression, description}]`) [8]. Part Studio: `POST /partstudios/d/{did}/w/{wid}/e/{eid}/features/updates` (`updateFeatures`, "updates only the parameters supplied") or `POST .../features/featureid/{fid}` (`updatePartStudioFeature`) on the `Variable` feature [9][10] | different shape | Two write paths by where the variable lives; values are expressions with units (`"40 mm"`), not document-unit floats; regeneration is implicit ("all operations that use the variable are automatically updated") [34]; the write response carries `featureStates`, so the rebuild check comes free [10]. The "never creates" guard is client-side. For size families, do not write at all: pass a `configuration` string to the read endpoints instead [17]. |
| `sw_rebuild(doc)` — force rebuild; list features in error/warning | `GET /partstudios/d/{did}/{wvm}/{wvmid}/e/{eid}/features` (`getPartStudioFeatures`) → `featureStates: {fid: {featureStatus: OK\|INFO\|WARNING\|ERROR\|UNKNOWN, inactive}}` [11][12] | different shape | There is no forced rebuild; the server regenerates on every edit. The status half maps cleanly and is also returned by every feature write [10]. `evalFeatureScript` returns `notices` for the same purpose [35]. Assembly `GET /assemblies/.../features` exists [36] but its state map was not confirmed. |
| `sw_mass_properties(doc, coord_system)` — mass, COM, inertia tensor (SI) about a named coordinate system or the COM | `GET /partstudios/d/{did}/{wvm}/{wvmid}/e/{eid}/massproperties?partId=&massAsGroup=&useMassPropertyOverrides=&configuration=` (`getPartStudioMassProperties`) [1]; `GET /parts/d/{did}/{wvm}/{wvmid}/e/{eid}/partid/{partid}/massproperties` (`getMassProperties`) [2]; `GET /assemblies/d/{did}/{wvm}/{wvmid}/e/{eid}/massproperties` (`getAssemblyMassProperties`) [3] | 1:1 about the COM; different shape about a frame | Response `bodies[partId or "-all-"] = {mass[3], centroid[9], inertia[27], principalInertia, principalAxes, volume, periphery, hasMass, massMissingCount}`; each scalar is a (value, min, max) triple "considering tolerance" [1][4]. "Parts must have density" [1]. Same numbers as the in-product tool, whose inertia is "calculated with respect to the center of gravity of the selected parts (not the Part Studio/assembly origin)" [4]; the tool's mate-connector option has no REST parameter. About a frame: (a) parallel-axis shift client-side from the centroid, with the frame from `evMateConnector` [6] or, for assemblies, the occurrence `transform` in `getAssemblyDefinition` [37]; or (b) `POST .../featurescript` with `evApproximateMassProperties({entities, density, referenceFrame})` — inertia "evaluated with respect to the reference frame, or with respect to the centroid if a reference frame is not specified", but "approximate" and density is passed in, not read from the material [5]. Part Studios only for (b). |
| `sw_get_dimensions(doc, names)` — `d1@Sketch1`-style dimensions with SI values and tolerance | `getPartStudioFeatures?featureId=` [11]; sketch features are `BTMSketch-151` with `constraints[]` of `BTMSketchConstraint-2` (`constraintType` LENGTH, DISTANCE, ANGLE, RADIUS, DIAMETER, ...; `drivenDimension`) [38]; feature parameters are `BTMParameterQuantity-147 {expression, value, units}` [39]; measurement via `POST .../featurescript` with `evDistance` / `evLength` [40] | different shape | No user-facing dimension names: a sketch dimension is a constraint node inside its sketch, a feature dimension is a `parameterId` (e.g. an extrude depth) on its feature. For "verify the interface contract" the honest analogue is measuring the geometry with FeatureScript, or reading the driving variable [7]. |
| `sw_set_tolerance(doc, dim, type, values)` — bilateral/symmetric/fit on a model dimension; drawing inherits | Tolerances exist on sketch and feature dimensions with types Default, No tolerance, Symmetrical, Deviation, Limits, Min, Max, Basic, Fit, Fit with tolerance, Fit (tolerance only) [13]; the spec exposes `GBTToleranceType` (same set), `GBTTolerancePrecision`, `BTToleranceString-3274 {value, upper, lower, classification}`, and a `BTMParameterTolerantQuantity-2579` parameter type whose fields are not published (`btType` only) [14] | different shape; write path unconfirmed | Would be an `updatePartStudioFeature` carrying a tolerant-quantity parameter; the public spec does not document that parameter's shape, so it needs a captured example from the browser client. "Not all sketch dimensions or Feature parameters can use tolerances" [13]. |
| `sw_custom_props(doc, values?)` — read all / create-or-overwrite title-block properties | `GET\|POST /metadata/d/{did}/{wvm}/{wvmid}/e/{eid}/{iden}/{pid}` (`getWMVEPMetadata` / `updateWVEPMetadata`, part level) [15][41]; `GET\|POST /metadata/d/{did}/{wvm}/{wvmid}/e/{eid}` (`getWMVEMetadata` / `updateWVEMetadata`, tab level) [42] | different shape | Read returns `properties[] {name, propertyId, value, valueType, editable, ...}`; write body is `{"properties":[{"propertyId":"...", "value":"..."}]}` — keyed by id, so the client maps names to ids from a read first [15]. Overwriting built-in properties (part number, revision, material) is the covered case; *creating* a new key, which `sw_custom_props` does implicitly, requires a company-defined property: "Properties" for Professional/Educator, "Custom properties" for Enterprise, on company-owned documents [16]. |

Also available on the Onshape side with no SolidWorks-MCP counterpart, all relevant to armature-cad:

- **Configurations.** `GET\|POST /elements/d/{did}/{wvm}/{wvmid}/e/{eid}/configuration` (`getConfiguration` / `updateConfiguration`) returns `configurationParameters[]` (enum, quantity with `rangeAndDefault`, boolean, string) and `currentConfiguration`, for Part Studios, Variable Studios, and Assemblies [17]; `POST /elements/d/{did}/e/{eid}/configurationencodings` (`encodeConfigurationMap`) turns `{parameterId, parameterValue}` pairs into the `configuration=` query string that nearly every read endpoint above accepts [18].
- **Feature list.** `getPartStudioFeatures` returns `features[]` (`featureId`, `featureType`, `name`, `suppressed`, `parameters[]`, `mateConnectorFeature`, `variableStudioReference`) plus `featureStates` and `sourceMicroversion` [11][12]. `getFeatureScriptRepresentation` gives the whole Part Studio as FeatureScript [43].
- **STEP export.** `POST /partstudios/d/{did}/{wv}/{wvid}/e/{eid}/export/step` and `POST /assemblies/.../export/step` with `BTBStepExportParams {stepVersionString: AP242|AP203|AP214, stepUnit, storeInDocument, includeExportIds, excludeHiddenEntities, destinationName}` [19]; poll `GET /translations/{tid}` until `requestState` goes `ACTIVE → DONE|FAILED`, "use a reasonable interval ... or use Webhooks" [20]; then `GET /documents/d/{did}/externaldata/{fid}` (`downloadExternalData`) with `resultExternalDataIds`, or the blob element if `storeInDocument` [21]. `createPartStudioTranslation` is the generic form (`formatName`, tessellation controls) [44]. Synchronous `GET /parts/.../partid/{partid}/stl` and `/parasolid` return a 307 redirect to the file [45].
- **Interference.** No REST endpoint: the spec has no path matching interference, collision, or clearance [46]. The product's Interference detection tool "detects and views any interference in a Part Studio or Assembly" [22]. In a Part Studio, `evalFeatureScript` with `evCollision({tools, targets})` returns collisions typed `NONE | INTERFERE | EXISTS | ABUT_* | TARGET_IN_TOOL | TOOL_IN_TARGET` [23]; the assembly-level check is out of reach.
- **Mate connectors as frames.** `getAssemblyDefinition?includeMateConnectors=true&includeMateFeatures=true` returns occurrences with a 4x4 `transform` "in the top-level assembly's coordinate system" [37]; in a Part Studio `evMateConnector` returns the `CoordSystem` of a named mate connector [6]. This is what carries `CONTEXT.md` frames into the mass-properties shift.

## Auth model

- **API keys** (the fit for a local check script). Created under My Account → Developer (or the Developer portal); "Individual accounts are capped at two (2) active API keys"; company/classroom/enterprise accounts are not capped; a key is valid only on the stack it was created on [24]. Scopes per key: `OAuth2ReadPII`, `OAuth2Read`, `OAuth2Write`, `OAuth2Delete`, `OAuth2Purchase`, `OAuth2Share` [25]; a read-only key POSTing gets 403 [28]. Two ways to send a key: **Basic** — `Authorization: Basic base64(access:secret)`, "Lowest security. For local testing only"; **Request signature** — headers `Date` (within 5 minutes), `On-Nonce` (≥16 alphanumeric characters, unique per request), and `Authorization: On <AccessKey>:HmacSHA256:<Signature>` over method, nonce, date, content-type, path and query string [24].
- **OAuth2** authorization-code flow at `https://oauth.onshape.com/oauth/authorize` and `/oauth/token`; bearer access tokens good for 60 minutes, refresh tokens for the lifetime of the grant; "All applications must authenticate with OAuth2 to be approved in the Onshape App Store" [26]. Apps registered under My Account count toward the user's limits; under Company settings, the company's [27].
- The OpenAPI document declares one security scheme, `OAuth2` authorization-code, with the six user scopes above [47].

## Rate limits

- **Per-endpoint:** "Specific rate limit values vary by endpoint" and are not published; exceeding one returns `429 Too Many Requests` with `X-Rate-Limit-Remaining` and `Retry-After` (the guide's example: `Retry-After: 450` seconds) [27][28].
- **Annual quota, by subscription:** Enterprise / Enterprise GOV 10,000 per full user; Professional 5,000 per user; EDU Student, Free, Standard 2,500 per user; EDU Enterprise 10,000 per enterprise; EDU Educator / Pro Discovery 2,500 per company [27].
- Counted: calls with API keys, calls with OAuth2 through private apps (charged to the app owner), and API Explorer calls under either — only when they return 2xx/3xx. Not counted: public App Store apps, the browser and mobile clients, webhook deliveries, and 4xx/5xx responses. Past the quota, "subsequent API requests are rejected with a 402 Response Code"; more calls "are available for purchase upon request" [27].
- Terms: "The API may not be used by any robot, spider, scraper or other automated means for data mining ... from the Onshape Public Documents" [27].

What 2,500 a year means for armature-cad: one loop closure is roughly four calls (`sessioninfo`, element list, `massproperties`, `getVariables`), so about 600 closures a year on Free if nothing else spends the budget; a STEP export costs its POST plus every poll; a general-purpose Onshape MCP server that lists and reads liberally would drain it in a few sessions. Cache ids, batch parts through `massAsGroup=false` on one Part Studio call rather than one call per part, and never poll faster than a few seconds.

## Plan restrictions

- **Free:** "For non-commercial use only. All Onshape Documents are accessible to the public." Standard is $1,500/user/year (private storage), Professional $2,500, Enterprise by quote; "Only paid plans support private data and commercial use" [29].
- **API on Free:** the developer limits table allocates "EDU Student / Free / Standard — 2,500 per User" annual calls [27], and the API-key guide's individual-account cap applies to any individual account [24]; together these document API-key access on the Free plan. The pricing page's comparison grid lists "Open API Integration — Effortlessly automate Onshape and integrate with business processes via its secure, user-friendly, and robust REST API" as a compared feature, but the grid is rendered client-side and the per-plan ticks are not in the static page [29] — see *Not confirmed*.
- **Metadata definitions:** company "Properties" (rename/display built-ins, add properties) are "only available for" Professional or Educator, "Custom properties" for Enterprise, and both apply to company-owned documents; "Users can only view these metadata definitions" [16].
- **FeatureScript** is listed on the pricing grid as a compared feature [29]; `evalFeatureScript` carries no plan gate in the spec [35]. Not verified per plan.

## What an Onshape path inside armature-cad minimally needs

Either a small MCP server beside `mcp/solidworks/` or a REST client imported by the check scripts; the surface is the same:

1. **Auth + addressing:** access/secret from the environment; Basic header for a local script, HMAC signing if it ever leaves the bench [24]. Resolve `did/wid/eid` from a pasted document URL, then `getElementsInDocument` to find a tab by name [33]. Confirm with `sessioninfo` [31]. Base URL `https://cad.onshape.com/api/v17` (or whichever version the client pins) [47].
2. **Six read calls:** `getElementsInDocument` [33], `getVariables` [7], `getPartStudioFeatures` (for `featureStates`) [11], the three `massproperties` [1][2][3], `getConfiguration` [17].
3. **One evaluation call:** `evalFeatureScript` with `evMateConnector` for the frame and either `evApproximateMassProperties(referenceFrame)` or a client-side parallel-axis shift; `evCollision` for Part Studio interference [5][6][23][35]. Only lambda expressions are accepted [35].
4. **Two write calls, gated behind a flag:** `updateFeatures` (Part Studio `Variable` feature) and `setVariables` (Variable Studio) with unit-carrying expressions; read back through `getVariables` [8][9]. Metadata writes by `propertyId` if the title block is to be filled from the definition [15].
5. **Export:** `export/step` → poll `/translations/{tid}` → `externaldata` download, with a polling floor and the AP242 default the documentation standards already name [19][20][21].
6. **Budget discipline:** a call counter with the annual quota as a hard ceiling, response caching keyed on `microversionId` (every mass-properties response carries one [1]), and no chatty discovery tools.
7. **Units:** parse formatted variable values; assume the mass-properties numbers are SI only after one calibration call against a part of known mass (see below).

Python needs `requests` and the standard library's `hmac`/`hashlib`; no SDK is required.

## Not confirmed

- **Units of the REST mass-properties numbers.** The spec says the response "includes the same information as in the Onshape Mass Properties Tool" and the guide's example (mass 0.0258, centroid 0.018) is consistent with kilograms and metres, but no page states the units outright [1][4]. Two forum threads that might were behind Onshape SSO. Calibrate with one call.
- **Layout of the 27-element `inertia` array** (nine tensor entries × value/min/max, in the example's order) is inferred from the guide's sample, not stated [4].
- **Free-plan API access as marketed.** Documented by the limits table [27]; the pricing grid's per-plan ticks for "Open API Integration" were not recoverable from the static page [29].
- **Tolerance write shape.** `BTMParameterTolerantQuantity-2579` and `BTToleranceSpec-3441` list only `btType` in the public spec [14].
- **Whether `setVariables` creates a missing variable** or only assigns existing ones ("Assign variables to a Variable Studio") [8].
- **Assembly `featureStates`** on `GET /assemblies/.../features` [36].
- **Per-plan availability of `evalFeatureScript`** and FeatureScript generally [29][35].
- **Onshape API Terms of Use** page (linked from the limits guide) returned 404 at the URL tried; only the limits guide's summary of it is cited [27].
